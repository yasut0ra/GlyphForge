# Renderer v2 比較結果

実施日: 2026-09-07。これは限定したオフライン比較であり、一般的なAA品質やキャラクター認識精度の評価ではない。

## 条件

- macOS 26.3 / arm64、Python 3.11.13、Pillow 12.1.1、NumPy 2.4.2。
- 幅40、Normal、最大2pass。同じ参照画像・v2フォント・ベースライン・前処理・charsetを使用。
- 猫、宇宙船、人物、非対称細線はPure ASCII、猫はUnicodeも追加。濃淡ランプはBlock Art。各2種類の行間で計12条件。
- v1は旧matcher・旧loss・旧hill climbing、v2は新matcher・multiscale loss・coordinate search。Normalの同時置換予算は0。
- 時間は各条件1回のmatcher＋optimizer実測。glyphの事前描画、前処理、指標計算、LLM、画像生成、ネットワークは除外。実行順序はv1→v2で、時間の信頼区間は未計測。

v1の字形位置やコピー処理まで再現した旧リリース全体との比較ではなく、損失・候補選択・探索の変更をまとめた比較である。各変更単独の寄与は未分離。

## 集計

| 指標 | v1 | v2 | 解釈 |
|---|---:|---:|---|
| 平滑化した前景のsoft F1（12条件平均） | 0.4381 | 0.5215 | 全12条件で改善 |
| Edge F1（線画10条件平均） | 0.5708 | 0.6408 | 線画10条件すべて改善 |
| Box-window SSIM（12条件平均） | 0.7600 | 0.7530 | わずかに悪化。特に濃淡ランプが課題 |
| 再構成loss（共通のv2尺度、12条件平均） | 0.7390 | 0.7106 | 3.8%減。ただし新方式自身の目的関数 |
| 変換・探索時間（12条件平均） | 2.184秒 | 0.822秒 | この実測では62.4%減 |

soft F1は両画像を9×9 box filterで平滑化し、`2 × sum(min(target, rendered)) / sum(target + rendered)`で計算した前景の重なり。新lossの二乗誤差・重みからは独立しているが、同じスケールの形状を評価する関連指標であり、人間の美的評価の代用ではない。

Edge F1は閾値0.08、位置許容1px。濃淡ランプには基準エッジがほぼなく、両方式とも0になるため、線画の集計から除いた。SSIMは11×11 box windowで、標準のGaussian-window版とは異なる。

## 判断と残る検証

線画では細い前景や輪郭を残しやすく、候補の再評価も速くなったため、v2を既定に採用した。濃淡ランプでは中間調の面積再現が改善する一方、文字の網点によりSSIMは悪化した。すべての指標・画像で改善したとはいえない。

予備比較では隣接2文字の探索を加えても同時置換が採用されず、Normal/Simpleでは無効化した。Detailedとfeedbackには拡張ポイントとして残すが、追加効果を主張しない。

このfixtureを見ながら調整した開発用評価であり、未知画像のhold-out試験ではない。次は40/60/80列、実画像、特徴の多い人物、異なる背景を含む固定データセットと、人間によるblind比較が必要。外部メモアプリへの実際の貼り付けとDOM表示の自動比較も未実施で、プレーンテキストが比例フォントでも崩れないという保証はない。

## 再現

```bash
make benchmark
```

`work/benchmark-v2/`にtarget / v1 / v2の比較PNG、実際のAAテキスト、数値JSONを生成する。保存済みの数値は [benchmark-v2-results.json](benchmark-v2-results.json)。設計は [design-v2.md](design-v2.md) を参照。
